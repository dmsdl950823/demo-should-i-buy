## 상태 기록 규칙
각 파일의 상태를 `TODO / IN_PROGRESS / BLOCKED / DONE` 중 하나로 갱신한다. 작업 결과에 수정 파일, 검증 명령과 결과, 미해결 항목을 간단히 기록한다. 실제 키와 응답의 민감 정보는 기록하지 않는다.

## 순서와 병렬화
00의 실제 호출 검증 전에는 앱 구현을 시작하지 않는다. 02에서 API 계약을 고정한 뒤 03과 04를 병렬로 진행한다. 테스트용 fixture는 허용하지만 실제 서비스 결과로 제공하지 않는다. 메인 에이전트가 공유 파일 수정과 통합을 조율하고 QA는 계약 확정 후 테스트 설계를 준비한다.
